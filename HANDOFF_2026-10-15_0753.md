Se verificó el arreglo con el **emulador de Firestore** (`@firebase/rules-unit-testing`) simulando el flujo completo antes de desplegar a producción — no se adivinó ni se desplegó a ciegas. Detalle completo en `PROGRESS.md`.

## Qué necesitas en el otro computador (y qué NO necesitas)

**Lo que ya está resuelto, no hace falta pedir ni copiar nada para esto:**
- `google-services.json` y `GoogleService-Info.plist` (config de cliente de Firebase) **ya están commiteados en el repo**. No son secretos — Firebase se protege con las Security Rules, no ocultando este archivo.
- El **keystore de firma de Android** no vive en ningún computador: EAS lo guarda remotamente asociado a tu cuenta Expo (`jrodrigogonzalezv`). Cualquier máquina donde hagas `eas login` con esa cuenta puede generar builds firmados igual que acá, sin transferir ningún archivo de firma.
- No hay ningún `.env`, API key de mapas, ni archivo de credenciales de servicio (`serviceAccountKey.json` o similar) en este proyecto — se evitó a propósito (ver `PROGRESS.md`, sección de mapas).

**Lo único que tienes que hacer en la máquina nueva** (todo es login interactivo con tu propia cuenta, 30 segundos cada uno — por eso no te paso tokens, ver nota de seguridad abajo):

```bash
git clone https://github.com/jrodrigogonzalezv/cuidary.git
cd cuidary
npm install

firebase login      # con rodrigo@system.cl (la cuenta Google que tiene acceso al proyecto Firebase "cuidary")
npx eas-cli@latest login    # con tu cuenta Expo: jrodrigogonzalezv

npx expo start --dev-client --tunnel   # para seguir iterando con recarga en vivo
```

- Firebase project id: `cuidary`
- Android package / iOS bundle id: `cl.cuidary.app`
- EAS projectId: ya está en `app.json` → `extra.eas.projectId` (`68080d9f-b79b-410e-bd1c-c71757163a94`)

### Por qué no te paso tokens/claves "copiables"

Me pediste que te diera "todas las claves" para no tener que volver a sacarlas. Revisé todo lo que este proyecto usa y, honestamente, **no hay ninguna clave reusable que debas copiar** — todo lo de arriba son logins interactivos con tu propia cuenta (Google/Expo), no API keys estáticas. Lo único que técnicamente podría "copiarse" son los tokens de sesión ya autenticados en esta máquina (de `firebase-tools`, de `eas-cli`, de `gh`) — y esos **no te los paso**, porque cada uno de ellos equivale a tener acceso completo a tu cuenta de Google/Expo/GitHub (no son claves de un servicio acotado, son credenciales de cuenta). Pegarlos en un archivo o en el chat sería más riesgoso que simplemente iniciar sesión de nuevo en la máquina nueva, y además este repo es **público** en GitHub, así que cualquier cosa así jamás debería ir commiteada. Si en algún momento quieres automatizar builds sin login interactivo (por ejemplo desde un CI), lo correcto es generar un **EAS access token** acotado solo a builds (`eas-cli` tiene esa opción) en vez de reusar tu sesión completa — avísame si quieres que lo dejemos configurado así.
